# MT5 Swing Execute

สกิลนี้เป็นที่เดียวที่เรียกเครื่องมือ `trade_*` ได้ สคริปต์ `mt5kit` ไม่มีโค้ดส่งคำสั่ง — มันแค่ตรวจซ้ำ เตรียมค่า และกระทบยอด
**คุณเป็นคนเรียกเครื่องมือ MCP เอง ด้วยค่าที่สคริปต์เตรียมให้ ห้ามแก้ตัวเลข**

## เมื่อไรใช้ได้ (ต้องเข้าข้อใดข้อหนึ่ง)

1. **authorization = mode** — ผู้ใช้เลือก "วิเคราะห์แล้ววางออเดอร์เลย" ตอนเริ่มรอบนี้ และ `scan` คืนแผนสถานะ PROPOSED
2. **authorization = user** — ผู้ใช้พิมพ์อ้าง Plan ID เช่น `ส่ง P-20261109-EURJPY-L-B-0800` (ไม่มี revision = ใช้ล่าสุด)

นอกเหนือจากนี้ห้ามส่งคำสั่ง การปิด Position และแก้ SL ทำได้เฉพาะเมื่อผู้ใช้สั่งชัดเจนพร้อม Ticket (ดูท้ายไฟล์)

## ขั้นตอน

**1. เตรียมรายการคำสั่ง** (ตรวจซ้ำ: บัญชี Demo, โควตา, ข่าว, โซนยังไม่ถูกแตะ, ราคายังเป็น Limit ได้, งบความเสี่ยงปัจจุบัน)

```bash
python3 -m mt5kit prepare-actions --run <run_id> --plans <plan_id>[,<plan_id>] --authorization <mode|user> [--include-cancels]
```

- `run_id` อยู่ในผลสแกน หรือขึ้นต้นของ plan ใน `ledger/ledger.json`
- `refused` ไม่ว่าง → บอกผู้ใช้ตามเหตุผล แล้ว **หยุดสำหรับแผนนั้น** ห้ามปรับราคา ห้ามเปลี่ยนเป็น Market ห้ามลองใหม่ด้วยค่าอื่น
- ได้ `{"refused": "..."}` ทั้งก้อน (เช่น execution ยังไม่เปิด, บัญชีไม่ใช่ Demo) → แจ้งผู้ใช้และหยุด

**2. แสดงตารางก่อนส่งเสมอ** — คู่, ประเภท, Lot, ราคาเข้า, SL, TP, หมดอายุ (เวลาไทย), Action ID

- authorization = user → ข้อความ "ส่ง …" ของผู้ใช้คือการยืนยันแล้ว
- authorization = mode → ผู้ใช้อนุญาตไว้ตั้งแต่ต้นรอบแล้ว
- ถ้าคำอธิบายของเครื่องมือ MCP ระบุว่าต้องให้ผู้ใช้ยืนยันค่าทุกตัว ให้ถามยืนยัน **ครั้งเดียว** สำหรับทุกรายการ ("ส่ง N ออเดอร์ตามตารางนี้ไหม?")

**3. ส่งทีละรายการตามลำดับใน `actions`** (CANCEL มาก่อน PLACE เสมอ)

- เรียกเครื่องมือชื่อ `tool` ด้วย `args` ตามที่ได้มา **ทุกค่า** ถ้าชื่ออาร์กิวเมนต์ไม่ตรง schema ของเครื่องมือ ให้หยุด แจ้งผู้ใช้ และแก้ `mt5kit/config/mcp-map.json` ก่อน ห้ามเดาเอง
- หลังเครื่องมือตอบ ให้บันทึกผลทันที: เขียนผลดิบทั้งก้อนลงไฟล์ `runs/<run_id>/responses/<action_id>.in.json` (ใช้เครื่องมือ Write) แล้วรัน

```bash
python3 -m mt5kit record-result --run <run_id> --action <action_id> --response runs/<run_id>/responses/<action_id>.in.json
```

- Timeout / ไม่รู้ผล → บันทึกเป็นผลที่ได้ (หรือ `{"status":"timeout"}`) แล้ว **ห้ามส่งซ้ำ** ข้ามไปขั้นที่ 4
- รายการไหนถูกปฏิเสธ → ส่งรายการถัดไปได้ ยกเว้นรายการที่พึ่งรายการนั้น

**4. กระทบยอดทุกครั้ง**

```bash
python3 -m mt5kit reconcile --run <run_id>
```

ตอบผู้ใช้: สถานะรวม (`success` / `partial` / `rejected` / `unknown`), Ticket ที่ยืนยันจาก MT5, ค่าที่โบรกเกอร์รับจริง, ที่อยู่รายงาน (`runs/<run_id>/report.html` ถูกอัปเดตส่วน "ผลดำเนินการ" แล้ว)
แยกให้ชัด: "วาง Pending สำเร็จ" ไม่ใช่ "Fill แล้ว" · สถานะ `unknown` = ยังไม่รู้ผล ต้องตรวจก่อนทำอะไรต่อ

## กฎที่ห้ามฝ่าฝืน

- ใช้เฉพาะ Pending Limit ตามแผน ห้ามเข้า Market และห้ามเปลี่ยน Entry/SL/TP เอง
- ล็อตใช้ตามที่ prepare-actions ให้ (อาจลดลงตามงบปัจจุบัน แต่ไม่เพิ่ม)
- ห้ามแก้ หรือปิด ไม้ที่ไม่ใช่ของสกิล (Manual / EA อื่น)
- ห้ามส่งซ้ำเมื่อผลไม่แน่ชัด — กระทบยอดก่อนเสมอ
- ห้ามแสดง Token หรือเลขบัญชีเต็ม

## แก้ SL / ปิด Position (เฉพาะเมื่อผู้ใช้สั่งชัดเจนพร้อม Ticket)

ใช้ค่าจาก `management` ในรายงานล่าสุด (`new_sl` สำหรับ MODIFY_SL) และแม่แบบใน `mcp-map.json` → `trade_templates.MODIFY_SL` / `CLOSE_POSITION`
ห้ามขยาย SL ออก (Long ต้องสูงขึ้นเท่านั้น, Short ต้องต่ำลงเท่านั้น) จากนั้นรัน `reconcile` หรือ `scan` ใหม่เพื่อยืนยันสถานะ
