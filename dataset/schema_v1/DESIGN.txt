CSV DATASET DESIGN v1 (DRAFT)

No market event data has been exported into these templates. Files contain column headers only except the populated dictionary and setup catalog.

Event layout: dataset/PAIR/YYYY-MM-DD/HH-mm-ss_sequence/
Each event contains M1.csv, M5.csv, M15.csv, event.csv, plan.csv, levels.csv and outcome.csv. ticks.csv is optional execution evidence.

M15: wider structure/context. M5: setup formation. M1: entry trigger. Multiple timeframes are a proposed design; their incremental value should be checked in time-separated evaluation.
Proposed inputs: 240 M1 bars, 288 M5 bars, 480 M15 bars. These are research defaults and must not be confused with measured history availability. Calculate indicators using prior warmup history before slicing windows.

Only causal input columns plus approved context belong in the feature loader. Pattern, side, entry/exit plans are supervision targets. outcome.csv contains future labels. ticks.csv may include both pre/post cutoff observations and must be phase-filtered. audit, split_control, join_key and future_label fields are excluded from model inputs unless explicitly reviewed.

Use price action to select setups, independently of outcomes. The catalog is a draft; exact thresholds and order/exit parameters must be registered before extraction. Human reviews should see data only up to decision time. Retrospective examples must be marked and kept separate.

Keep original raw M1 history in a separate per-pair monthly archive. Do not replace missing data with zero or fabricated candles. Unexplained gaps, insufficient warmup, unverified server offsets, missing ticks and unresolved SL/TP order are explicitly flagged.

Historical commission/slippage may not be available. Preserve unknown values. Spread and fill slippage embedded in executable entry/exit prices must not be deducted twice.

Split by global chronological periods across pairs. Purge samples whose full input-to-outcome intervals overlap other splits; include an explicit embargo. Fit scalers on training only. Retain original prevalence for validation and test.

See schema.json for precise definitions, defaults, causal rules and sources.
