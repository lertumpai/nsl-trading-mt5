# MT5 Swing Analyze

ทำงานจากรากโปรเจกต์ (โฟลเดอร์ที่มี `mt5kit/`) ทุกคำสั่งคือ `python3 -m mt5kit ...` และพิมพ์ผลเป็น JSON สั้น ๆ
โค้ดเป็นคนอ่านข้อมูล MT5 หาสัญญาณ คำนวณล็อต และสร้างกราฟ **คุณไม่ต้องอ่านแท่งเทียนเอง** หน้าที่ของคุณคือ
ถามโหมด → รันคำสั่ง → สรุป Macro → เขียนคำอธิบายสั้น → ส่งผลให้ผู้ใช้

## ขั้นที่ 0 — ถามโหมดก่อนทำอะไรทั้งหมด

ถ้าข้อความผู้ใช้ยังไม่บอกโหมดชัดเจน ให้ใช้ AskUserQuestion ถาม **คำถามเดียว**:

- `วิเคราะห์แล้ววางออเดอร์เลย` — ถ้ามีแผนผ่านทุกกฎ จะวาง Pending ทันที (ไม่เกินโควตาวันละ 2 และอยู่ใน Risk profile)
- `เอาแค่แผนมาอ่าน` — วิเคราะห์และทำรายงาน แต่ไม่ส่งคำสั่ง (สั่ง `ส่ง {Plan ID}` ทีหลังได้)

กฎ: ผู้ใช้บอกโหมดแล้ว → ไม่ถามซ้ำ · ตอบไม่ชัด → `plan_only` · รอบที่รันตามเวลาโดยไม่มีคนตอบ → ใช้ `scheduled_default_mode` ใน `account-profile.json` (ค่าเริ่มต้น `plan_only`)

โหมด → อาร์กิวเมนต์: วางเลย = `--mode analyze_and_place` · แผนอย่างเดียว = `--mode plan_only`

## ขั้นที่ 1 — ตรวจความพร้อม

```bash
python3 -m mt5kit status
```

ถ้า `next_steps` ไม่ว่าง ให้ทำตาม [references/setup.md](references/setup.md) ก่อน แล้วค่อยสแกน
ถ้า `lock_held` = true แปลว่ามีอีกรอบกำลังทำงาน ให้รอ ห้ามลบไฟล์ล็อกเอง (ยกเว้นเก่ากว่า 15 นาที ซึ่งโค้ดจัดการให้)

## ขั้นที่ 2 — Macro (วันละครั้ง ในรอบแรกของวัน)

ถ้า `macro_today` ยังไม่มีไฟล์ของวันนี้:

```bash
python3 -m mt5kit macro-template      # สร้างไฟล์ runs/macro/<วันที่>.json
```

แล้วมอบงานให้ subagent `macro-news` (หรือค้นเว็บเอง) กรอกไฟล์นั้นตาม [references/news-macro.md](references/news-macro.md)
ใส่ `conflict` เฉพาะเมื่อข่าว/นโยบายขัดกับทิศนั้นชัดเจน นอกนั้นให้ `neutral` หรือ `support`
COT ดึงสัปดาห์ละครั้งพอ: `python3 -m mt5kit cot` (ถ้าดึงไม่ได้ ให้ปล่อยไว้ ห้ามสร้างข้อมูลแทน)

## ขั้นที่ 3 — สแกน

```bash
python3 -m mt5kit scan --mode <plan_only|analyze_and_place>
```

ผลลัพธ์มี `decision`, `plans`, `management`, `scan`, `gates`, `warnings`, `run_id`, `narrative_file`, `report_html`
ถ้าได้ `error` ให้รายงานผู้ใช้ตามจริงและหยุด (เช่น เชื่อม MCP ไม่ได้) ห้ามเดาข้อมูล
ถ้า `mode` ในผลเปลี่ยนเป็น `plan_only` ทั้งที่ขอวางเลย ให้บอกเหตุผลจาก `warnings`

## ขั้นที่ 4 — เขียนคำอธิบายสั้น แล้วสร้างรายงาน

เขียนไฟล์ตาม `narrative_file` (รูปแบบเต็มใน [references/report.md](references/report.md)):

```json
{"overview": "ภาษาไทยง่าย ไม่เกิน 4 ประโยค: ตอนนี้ทำอะไร เพราะอะไร",
 "per_plan": {"<plan_id>": ["เหตุผลข้อสันนิษฐาน 1", "ข้อ 2"]}}
```

- เขียนเฉพาะข้อความ ห้ามพิมพ์ราคา ล็อต หรือเงินใหม่ (โค้ดใส่ตัวเลขให้แล้ว และจะตัดตัวเลขที่ไม่ตรงทิ้ง)
- เรื่องสถาบันต้องเป็นข้อสันนิษฐาน เช่น "อาจเป็นจุดที่…" ห้ามเขียนว่า "สถาบันเข้าแล้ว"
- ไม่มีแผน → อธิบายว่ารออะไร และอะไรจะทำให้กลับมาพิจารณา

```bash
python3 -m mt5kit render --run <run_id>
open runs/<run_id>/report.html        # macOS: เปิดรายงานในเบราว์เซอร์
```

## ขั้นที่ 5 — ตอบผู้ใช้

ตอบในแชตสั้น ๆ 3–6 บรรทัด: คำตัดสิน, แผนแต่ละอัน (คู่ ฝั่ง Entry/SL/TP ล็อต เงินเสี่ยง R:R เวลาหมดอายุ), การจัดการไม้เดิม, ที่อยู่ไฟล์รายงาน
โหมดแผนอย่างเดียว → บอกว่าพิมพ์ `ส่ง <plan_id>` เพื่อวางได้

ถ้าโหมดคือ `analyze_and_place` และ `plans` ไม่ว่าง → ทำต่อด้วยสกิล **mt5-swing-execute** ทันทีในรอบเดียวกัน ด้วย `--authorization mode`
ถ้า `management` มี `CANCEL` ของไม้ที่เป็นของสกิล ให้ส่งต่อด้วย `--include-cancels`
`MODIFY_SL` และ `PROPOSE_CLOSE` เป็นแค่ข้อเสนอ ต้องรอผู้ใช้สั่งเอง

## กฎที่ห้ามฝ่าฝืน

- สกิลนี้ **ห้ามเรียกเครื่องมือ MCP ที่ขึ้นต้นด้วย `trade_`** (การส่งคำสั่งอยู่ในสกิล execute เท่านั้น)
- ห้ามแก้ `mt5kit/config/strategy-v2.json` ระหว่างรอบ หรือแก้เพื่อให้ได้สัญญาณ
- ห้ามใช้ M1–M15 หาเหตุผลเข้า และห้ามเสนอเข้า Market ไล่ราคา
- ห้ามบอกว่าระบบจะเฝ้าราคา/ยกเลิกก่อนข่าวเองระหว่างรอบ (ระบบพึ่ง SL/TP/Expiry ของโบรกเกอร์)
- ห้ามอ่านหรือแสดง Token ใน `.mcp.json`
